# Как снимались цифры

Все замеры сделаны на одном ноутбуке: Intel AX201 (iwlwifi), Wi-Fi 5 ГГц,
сигнал −22…−25 дБм, ядро 7.2 (Omarchy 4). Результат у вас будет другим,
методика ниже.

## Всплески задержки

Пинг до роутера, 200 пакетов с интервалом 0,2 с, без другой нагрузки на
канал. Считается число ответов дольше 20 мс.

```bash
ping -i 0.2 -c 200 192.168.1.1
```

| Состояние | Всплесков >20 мс | Максимум |
|---|---|---|
| `power/control=auto` (два замера) | 16 и 11 | 202 и 205 мс |
| `power/control=on` (два замера) | 0 и 1 | 11 и 50 мс |

Переключается так (нужен root):

```bash
echo on   | sudo tee /sys/class/net/wlo1/device/power/control
echo auto | sudo tee /sys/class/net/wlo1/device/power/control
```

Тот же эффект без root даёт поток мелких пакетов. Ниже `auto` и разная
частота, по 150 пингов:

| Поток на роутер | Всплесков >20 мс | Максимум |
|---|---|---|
| нет | 7–17 | 189–203 мс |
| 10 Гц | 9 | 100 мс |
| 25 Гц | 8 | 36 мс |
| 50 Гц | 3 | 40 мс |
| 100 Гц | 0 | 11–15 мс |

Поэтому в `netmode keepalive` 100 пакетов в секунду.

## Несколько соединений

```bash
netmode get https://proof.ovh.net/files/10Mb.dat -o a.bin -n 1
netmode get https://proof.ovh.net/files/10Mb.dat -o b.bin -n 16
sha256sum a.bin b.bin
```

24,1 с против 5,3 с, суммы совпали. Сервер Cloudflare для проверки не
подходит: он не отдаёт диапазоны, и `netmode get` честно качает одним потоком.

## Что не помогло

- Сменить DNS на Cloudflare. Это полезно само по себе (запрос без кэша
  с 125 до 8 мс), но к рывкам видео отношения не имеет.
- Искать другой адрес видеосервера AnimeLib. `video1.cdnlibs.org` и
  `video2.cdnlibs.org` у всех резолверов отдают один и тот же адрес.
- Отключить QUIC. Он работает (проверено на Google и cloudflare-quic.com).
